# 校长模拟器 · 全局 UI 设计规范

**版本：** V1.0  
**设计平台：** 移动端 H5 / 手机浏览器 / App  
**设计方向：** 治愈系校园经营 + 轻策略模拟 + 日式经营游戏

---

# 1. 产品视觉定位

## 1.1 核心设计理念

将《校长模拟器》塑造成一款具有日式经营游戏氛围的校园模拟经营手游。

玩家扮演一所高校的校长，通过经营校园、建设设施、招聘教师、发展学科、筹集资金和完成升本申报，逐步将一所普通专科院校发展为高水平大学。

视觉上需要体现：

- 治愈：柔和、温暖、舒适，不使用强烈刺激的颜色。
- 校园：具有春夏秋冬的校园场景和生活气息。
- 经营：通过数据、进度、任务和奖励反馈经营成果。
- 成长：让玩家直观看到学校从简陋到繁荣的变化。
- 策略：通过不同发展路线和资源分配产生经营决策。

## 1.2 视觉关键词

Cozy / Pastel / Anime / Campus / Simulation / Management / Growth

避免：
- 传统 ERP 管理后台风格。
- 大面积纯白、灰色的表格界面。
- 过多复杂的图表和密集的数据。
- 过度科技感、赛博朋克风格。
- 过度卡通化、低龄化的儿童游戏风格。

采用柔和的天空蓝到奶油白渐变。

推荐：
- 顶部：#DCEEFF
- 中间：#F1F5FA
- 底部：#F8F5F0

不建议整个页面使用纯白背景。

# 3. 字体与排版规范

## 3.1 字体

优先使用：

- iOS：PingFang SC
- Android：系统默认中文字体
- Web：优先使用系统无衬线中文字体

## 3.2 字号体系

| 类型 | 字号 |
|---|---:|
| 页面主标题 | 22px |
| 模块标题 | 18px |
| 卡片标题 | 16px |
| 正文 | 14px |
| 辅助描述 | 12px |
| 标签 | 11px |
| 核心数值 | 26～32px |

## 3.3 字重

- 页面标题：700
- 模块标题：600
- 卡片标题：600
- 正文：400
- 辅助说明：400

核心数值使用较粗字重，突出学校评分、资金、招生数量等关键指标。

# 4. 手机端布局规范

## 4.1 设计尺寸

基准画布：390 × 844px。

适配范围：320～430px。

所有页面必须采用响应式布局，不允许使用固定宽度导致横向溢出。

## 4.2 页面安全区域

- 顶部适配系统状态栏。
- 底部适配 iPhone Home Indicator。
- 固定导航不能覆盖页面内容。
- 弹窗需要考虑键盘弹出后的可视区域。

## 4.3 页面边距

| 项目 | 规范 |
|---|---:|
| 页面左右边距 | 16px |
| 卡片内部边距 | 14～16px |
| 卡片之间间距 | 12px |
| 模块之间间距 | 18～24px |
| 按钮高度 | 44～48px |
| 圆形图标按钮 | 44px |

## 4.4 页面滚动

- 主页面采用纵向滚动。
- Tab 栏可固定在页面顶部。
- 底部导航固定。
- 数据卡片允许局部横向滚动。
- 禁止整个页面横向滚动。

# 5. 卡片组件规范

## 5.1 普通卡片

- 背景：#FFFDF8 或白色。
- 圆角：16px。
- 阴影：0 4px 14px rgba(50,70,100,0.08)。
- 边框：1px solid rgba(120,150,190,0.12)。

## 5.2 重点卡片

用于学校评分、学期目标、重点任务。

- 圆角：18～22px。
- 背景可采用浅蓝渐变。
- 重要数据使用大字号。
- 可以配合小型插画或图标。

## 5.3 特殊卡片

用于：
- 校园新闻。
- 随机事件。
- 年度总结。
- 成就奖励。

可以使用插画背景、暖色渐变和更丰富的装饰。

# 6. 按钮规范

## 6.1 主按钮

校园蓝背景，白色文字。

- 高度：46px。
- 圆角：23px。
- 字号：15px。
- 字重：600。

适用：去处理、开始经营、确认建设、提交申报。

## 6.2 次级按钮

白色背景、浅蓝边框、蓝色文字。

适用：查看详情、稍后处理、返回。

## 6.3 危险操作

采用柔和红色，不与普通主按钮混淆。

## 6.4 交互反馈

- 点击时轻微缩放。
- 操作成功时出现反馈动画。
- 不允许出现没有点击反馈的按钮。
- 不允许使用纯装饰性假按钮冒充可操作控件。

# 7. 图标与插画规范

## 7.1 图标风格

统一采用圆润、轻量、带有轻微立体感的图标。

推荐：
- 校园建筑：教学楼、宿舍、图书馆。
- 人物：教师、学生、校长。
- 经营：金币、奖杯、任务、进度。
- 学科：书本、实验器材、计算机。

图标应保持统一的视觉语言，不混用大量不同风格的素材。

## 7.2 人物立绘

校长：
- 成熟、亲和、专业。
- 作为游戏核心引导角色。
- 在首页、事件、年度报告中重复出现。

教师：
- 二次元人物立绘。
- 男女角色均衡。
- 通过服饰、表情、配色形成差异。

学生：
- 青春、活泼。
- 主要用于校园新闻、随机事件和招生相关场景。

## 7.3 校园建筑

采用日式经营游戏常见的等距视角或轻透视插画。

建筑风格：
- 教学楼。
- 实验楼。
- 图书馆。
- 宿舍。
- 体育馆。
- 实训基地。

建筑应支持等级变化和视觉升级。

# 8. 全局导航规范

手机端使用底部五栏导航。

| 导航 | 主要功能 |
|---|---|
| 首页 | 校园总览、学校经营状态 |
| 办事 | 待办任务、随机事件 |
| 学校 | 建设、学科、学校概况 |
| 成就 | 学校成长、经营成果 |
| 我的 | 设置、存档、帮助 |

规范：
- 固定在屏幕底部。
- 高度约 64～72px，不含系统安全区域。
- 当前选中项使用校园蓝。
- 未选中项使用灰蓝色。
- 图标在上，文字在下。
- 点击区域不小于 44px。

# 9. 核心页面设计规范

## 9.1 首页

首页是整个游戏最重要的页面。

布局顺序：

1. 顶部校长头像、学校名称、学年、资金、评分。
2. 春日校园主视觉。
3. 本学期经营目标。
4. 待办事务。
5. 学校成长数据。
6. 校园新闻和随机事件。
7. 快捷功能入口。
8. 底部导航。

首页重点：让玩家感受到自己正在经营一所真实成长的学校。

## 9.2 学校页面

采用顶部 Tab：

- 概况
- 建设
- 学科

概况展示：
- 学校综合评分。
- 办学层次。
- 校园面积。
- 学校容量。
- 在校生。
- 教职工。
- 当前发展路线。

建设展示：
- 建筑插画。
- 建筑等级。
- 建设成本。
- 升级条件。
- 建设进度。

学科展示：
- 六个系的实力。
- 学科发展进度。
- 学科建设成果。
- 学科短板提示。

## 9.3 教师页面

采用教师角色卡片。

展示：
- 人物头像。
- 姓名。
- 职称。
- 所属学科。
- 学历。
- 才华。
- 忠诚度。

支持：
- 招聘。
- 培养。
- 晋升。
- 调动。
- 教师详情。

## 9.4 申报页面

顶部显示申报路线：

- 普通本科。
- 职业本科。
- 212。
- 986。
- D9。

每条路线独立显示：
- 综合评分。
- 学科要求。
- 教师要求。
- 校园建设要求。
- 经费要求。
- 风纪要求。
- 其他必要条件。

状态：
- 满足：绿色。
- 接近满足：橙色。
- 不满足：灰色或红色提示。

每个未满足条件都应能跳转到对应经营功能。

## 9.5 年度报告

年度报告采用独立结算页面。

展示：
- 年度综合评分。
- 资金变化。
- 招生变化。
- 教职工变化。
- 学科成长。
- 本年度重大事件。
- 下一年度经营建议。

增加年度评价等级和奖励反馈。

# 10. 游戏反馈与动效规范

动效应该轻快、克制，不影响操作效率。

| 场景 | 动效 |
|---|---|
| 获得资金 | 金币数字递增 |
| 完成任务 | 绿色完成动画 |
| 建设成功 | 建筑升级展示 |
| 招聘成功 | 教师角色入场 |
| 学科成长 | 进度条增长 |
| 年度结算 | 报告逐项展示 |
| 解锁成就 | 奖杯和奖励弹窗 |

动效建议：
- 普通过渡：150～250ms。
- 卡片出现：200～300ms。
- 重点奖励：300～500ms。

提供减少动态效果的兼容方案。

# 11. 弹窗与交互规范

优先采用手机底部抽屉式弹窗。

适用：
- 任务详情。
- 教师详情。
- 建筑升级。
- 资源消耗确认。
- 随机事件选择。

大型内容可以采用全屏页面。

确认操作必须明确展示资源消耗和结果，不允许误触造成重要资源损失。

# 12. 响应式适配规范

| 屏幕宽度 | 适配策略 |
|---|---|
| 320～359px | 紧凑布局，减少并排信息 |
| 360～389px | 标准手机布局 |
| 390～430px | 标准布局，适当增加留白 |
| 430px以上 | 限制内容最大宽度，避免过度拉伸 |

必须满足：
- 所有内容自适应。
- 图片保持正确比例。
- 文字允许合理换行。
- 按钮不被挤压。
- 底部导航固定。
- 页面没有水平溢出。

# 13. 组件复用原则

全项目统一使用以下组件：

1. AppHeader：顶部资源栏。
2. BottomNavigation：底部导航。
3. GameCard：通用经营卡片。
4. StatCard：数值卡片。
5. ProgressBar：成长进度条。
6. TaskCard：任务卡片。
7. CharacterCard：人物卡片。
8. BuildingCard：建筑卡片。
9. PrimaryButton：主按钮。
10. SecondaryButton：次按钮。
11. GameModal：游戏弹窗。
12. EventBanner：事件横幅。
13. RewardPopup：奖励弹窗。
14. TabNavigation：顶部标签导航。

所有页面优先使用统一组件，禁止每个页面单独实现一套视觉风格。

# 14. 开发验收标准

视觉验收：
- 整体符合治愈系校园经营风格。
- 不再出现传统后台管理系统风格。
- 所有页面使用统一颜色、字体和圆角规范。
- 插画风格保持统一。

功能验收：
- 所有原有游戏业务逻辑保留。
- 所有原有数值和经营规则保留。
- 导航、按钮、Tab 均可正常交互。
- 弹窗可以正常关闭。
- 操作反馈准确。

移动端验收：
- 320px、360px、375px、390px、414px、430px 均正常。
- 无横向滚动。
- 无内容遮挡。
- 底部导航不覆盖内容。
- 安全区域适配正常。
- 软键盘弹出时输入区域可见。

# 15. 最终设计原则

**让玩家感觉自己不是在操作一个高校管理后台，而是在亲手经营一所不断成长的大学。**

所有页面围绕以下三个目标：

1. 好看：春日校园、二次元角色、温暖的游戏氛围。
2. 好玩：任务、成长、奖励、随机事件。
3. 好用：手机优先、操作简单、数据清晰。

以上规范作为《校长模拟器》后续所有 UI 页面重构的统一设计基准。

# 16. 与现网四栏导航的映射（本轮）

现网底部导航暂为四栏，对应关系：

| 现网 | Design System |
|---|---|
| 办事 | 首页经营总览 + 待办 / 过问 |
| 学校 | 学校（概况 / 建设 / 学科） |
| 教师 | 教师管理（后续可并入学校入口） |
| 申报 | 升格与项目申报（后续可从首页快捷进入） |

「成就 / 我的」待有真实数据与玩法后再扩为五栏。组件代码统一使用 Campus* 命名，与本文 §13 文档名一一对应。
