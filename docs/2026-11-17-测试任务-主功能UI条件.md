## 验收范围（必须亲自核对）

### A. 主功能链路

1. 启动页：选学校类型、改校名、开始任期 / 继续上一届
2. 办事：待办事项进入抉择、选项生效、返回后状态变化；每年结果 / 今年过问可切换
3. 学校：概况 / 建设 / 学科切换，数据展示与办事页一致
4. 教师：名册、详情进入/返回、筛选/培养/评估相关入口可点
5. 申报：升本双路径进度、条件对比筛选（全部/未达成/已达成）、展开明细、选择升本路线按钮状态合理
6. 跨页 pending：「有一件事等你拍板」在有 scene 时出现在学校/教师/申报，点回办事

### B. UI 展示

1. 与近期 Campus UI 风格一致：奶油卡片、天空蓝、软 3D campus 图标，无大面积纯黑、无破版横滚
2. 启动页、事件抉择、年终简报（若能触发）、结局页（若能触发）与四个主 Tab 视觉统一
3. 手机宽度约 390 可看：卡片圆角、底栏不挡内容、英雄区/双路径卡不错位
4. 图标缺失、灰块、文字溢出、按钮不可点要记缺陷

### C. 条件完成逻辑

1. 申报页分组进度（综合实力 / 教学师资 / 资金保障 / 校园建设 / 学校治理）与展开后真实 gate 条数一致
2. 状态标签「已达成 / 进行中 / 待提升 / 未达成」与 ordinary/vocational 两边完成数关系合理
3. 过滤「未达成」「已达成」不漏项、不误伤
4. 未满足条件时不能误显示可申报成功；满足条件时按钮/文案不自相矛盾
5. 重要结论追到 `game.js` 里 `pathGates` / `applyCompareGroups` / `applySheet` 等具体位置
