## 功能错

### F1. 「教学楼」被算进「教学师资」，分组进度失真

- **位置**：`game.js` → `applyCompareGroups`（约 4479–4517 行），师资正则 `re: /教学|硕博|双师/`
- **现象**：申报条件对比里「教学师资」显示「普通 1/3 · 职业 1/2」；展开后普通侧三条为：教学、硕博教师、**教学楼**。同页「校园建设」展开里再次出现「教学楼 1/2」。
- **违反点**：C.1 分组进度应对应真实 gate 分类；教学楼属于校园建设，不应进入师资组，更不应两侧重复计数。
- **证据**：
  1. 浏览器展开「教学师资」可见 `教学楼 1 / 2`。
  2. 代码：`/教学/` 会匹配标签「教学楼」；校园组正则也含 `教学楼`，故同一 gate 进两组。
  3. 新开局/建设后路径卡为 `6/16`、`8/14`，但师资组多算 1 条后，组间条数之和大于单路径 items 总数。
- **建议**：师资正则改为更精确匹配，例如 `/^教学$|硕博|双师/`，或对 label 做白名单/`id` 分组，禁止子串误伤「教学楼」。

### F2. 跨页再开申报会冲掉未完成的办事 scene

- **位置**：`game.js` → `openQueue`（约 873–876 行）；`doApply`（约 1543–1558 行）；`pendingBanner`（约 3810–3815 行）
- **现象**：办事里点「学科建设/引进人才」进入抉择后，切到学校/申报会出现「有一件事等你拍板」。若在申报页再点「选择升本路线」，scene 变成「升本走哪条」，原先「建设哪个系 / 人才引进到哪个系」丢失。
- **违反点**：A.6 pending 语义是提醒先回办事拍板；不应在其它页用新 action 静默覆盖未完成抉择。
- **证据**：
  1. 实操：`建设哪个系` → 学校页 pending 出现 → 申报点 CTA → 标题变为「升本走哪条」，原文案不再存在。
  2. `openQueue` 直接 `state.queue = items` 并 `state.scene = shift()`，无保护原 scene。
- **建议**：`phase === "scene"` 或已有 `state.scene` 时，禁用申报/其它会 `openQueue` 的入口，或只允许 pending 回跳；至少弹确认并保留原 queue。

### F3. 未达标时申报主按钮与英雄文案仍像「现在就能报」

- **位置**：`game.js` → `applySheet`（约 4559–4570 行）、`applyButton`（约 4441–4456 行）、`commitBachelor`（约 1593–1598 行）
- **现象**：路径仅 `6/16`、`8/14` 时，英雄区仍写「当前可申报 · 2项」，底部「选择升本路线」可点；点进路线后再由 `commitBachelor` 打回缺口页。
- **违反点**：C.4「未满足条件时不能误显示可申报成功」——逻辑层挡住了，展示层仍像可申报。
- **证据**：实操 CTA `disabled === false`；选普通本科后标题「普通本科还递不出去」，正文列出综合评分/教学/四系/理学/占地/楼宇等缺口。
- **建议**：未满足任一路条件时：弱化英雄文案（如「当前可准备 · 2 条路线」）、禁用或改成「查看缺口」；与 212+ 档已有「还有 X 项没到」提示对齐。

## UI 明显坏

### U1. 筛选标签「未达成」实际包含「待提升 / 进行中」

- **位置**：`game.js` → `applyCompareSection`（约 4522–4526 行）；文案 tabs `["open","未达成"]`
- **现象**：点「未达成」后仍列出「综合实力｜待提升」「教学师资｜待提升」「校园建设｜未达成」。
- **违反点**：B/C 文案与过滤语义不一致，玩家会以为「待提升」不该出现在「未达成」。
- **证据**：过滤实现为 `g.status.kind !== "done"`；实操结果与代码一致。
- **建议**：改文案为「未完成」/「进行中」；或拆成「未达成」= `lock`，另加「进行中」。

## 可选改进

### O1. 教师重名

- **位置**：教师名册（新开局「老专科」）
- **现象**：同时出现两名「周修远」（工学副教授、计算机讲师）。
- **建议**：生成名时按在职名单去重。

### O2. 教师详情头像与姓名性别观感不一致

- **位置**：教师详情（例：赵修远）
- **现象**：姓名偏男性，立绘为女性形象（随机立绘池）。
- **建议**：立绘按性别/姓氏池对齐，或弱化性别暗示。

### O3. 学校概况在校生高于容量无强调

- **位置**：学校 → 概况
- **现象**：示例开局见在校生 4000 / 容量 2800，无醒目超员提示。
- **建议**：超员时用告警色或短句提示（若属规则内压力，也应让玩家看见）。

### O4. 列表底部条目易被底栏挡住点击

- **位置**：教师列表等长列表 + `.campus-nav`
- **现象**：未滚到中部时，底部教师卡点击会被底栏拦截（自动化亦报 click intercepted）。
- **建议**：检查列表底部留白是否足够；卡片命中区避开 nav。
